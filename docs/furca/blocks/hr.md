# Блок hr — кадры: человек, условия его работы и точки, на которые ложатся его деньги

Текущая задача — **T221** ([issue #194](https://github.com/GarroV/maximus/issues/194),
решение **D055**): затраты человека разносятся по точкам, к которым он привязан.
Одна точка — целиком на неё, несколько — делятся, ни одной — это сеть.

Рабочая копия: `~/Documents/workbench/worktrees/maximus-hr`, ветка `feat/hr-unit-split`.
Стенд: `docker compose -p maximus-hr`, порты 8110 (приложение), 8111 (Postgres),
8112 (демо), 8113 (healthcheck).

Прежние задачи блока — T164, T197, T210 — приняты и закрыты; как и почему
сделаны — в `git log`.

**Что блок отдаёт — справочник людей и условий их работы:**

| Адрес | Что это |
|---|---|
| `/directory/employees/` | люди: список, карточка, заведение, увольнение, точки человека |
| `/directory/groups/` | группы расчёта и их условия |
| `/directory/groups/raise/` | массовое изменение ставок |
| `/directory/positions/` | должности (вилка ставки) |
| `/directory/units/`, `/directory/legal-entities/` | точки и юрлица |
| `/directory/calendar/` | производственный календарь по месяцам |

**Что блок потребляет:**

- правила страны и уровни переопределения из `core.rules` — схема расчёта и мера
  работы выбираются **из списка, известного правилам**, а не вводятся текстом;
- версионирование по датам из `core` (D020) — условия найма и привязка к точкам
  не правятся на месте, а заводят новую версию;
- контекст пользователя из `web` — права `rules.manage` и `directory.manage`
  (последнее после D059 есть и у оперативного директора, и у бухгалтера);
- механизм разнесения фактов по точкам (`allocation_plan`, `allocate_fact`) — им
  разносится ФОТ сетевого человека; второй такой механизм не пишется.

**Что блок отдаёт наружу движку:** через таблицы условий найма —
`employee_id → (схема расчёта, мера работы, ставка, коэффициент, группа, точки с
долями)` на дату. Движок `src/payroll/` читает это и не знает про экраны;
обратной зависимости нет и заводить её нельзя.

**Инвариант:** изменение условия задним числом не пересчитывает закрытый период
молча — разница ложится помеченной дельтой в текущий (D020).

## Definition of Done (T221)

- [x] У человека набор точек вместо одной, версионированный по датам (T197, T210)
- [x] Затраты делятся между его точками; доля у строки переопределяет, пусто — поровну
- [x] Управляющий видит своего человека, даже если тот привязан и к чужой точке —
      проверено ролью `app_user`, включая запись и отсутствие расширения чужого доступа
- [x] Набор решает, а не точка строки табеля (D085): задан — по нему; «вся сеть»
      (строка привязки без точки, `0271`) — на все точки общим правилом «поровну»
      (`0270`); не задан вовсе — по-старому, точка строки
- [x] «Вся сеть» выбирается на карточке явной галкой; пустая форма отвергается
- [x] Табель и ведомость говорят, куда идут деньги: «делится: NS1, NS2»,
      «целиком на NS1», «Вся сеть»

## Где стоим

T221 доделан по D085 и по разбору прав записи, слит с master (30.09), всё
запушено в `feat/hr-unit-split`. Как устроено — `git log` (`f9f565e`, `4301044`,
`80e96de`), докстринги `0271`, `0272`, `core/people_units.py`, `payrun/posting.py`.
Запись общих правил и привязок сужена (`0272`). Проводку ведомости мимо среза
ведёт только владелец схемы (сид, команды); ролью `app_user` — только полный
доступ, а без человека в контексте — отказ. Неразнесённый после проводки ФОТ
останавливает утверждение словами.

По разбору: права записи (CRITICAL, HIGH) — `0272`; (а) проводка под срезом —
отказ урезанной роли и `app_user` без человека; (б) перекрытие общих правил —
исключение с `SHARED_TENANT`; (в) «правила не заводятся при заведении
пространства» — не воспроизводится: правило общее, новое пространство его
видит (сторож в `test_payroll_across_units`). Дыра рядом — справочник строк P&L
заводит только сид — вне T221, [#278](https://github.com/GarroV/maximus/issues/278).

**Умолчание способа деления** (открытый пункт #194, за владельцем): «поровну»
(`even`) — строки `allocation_rules` с пустым `tenant_id` на `labour_cost` и
`payroll_taxes`, с 2000-01-01. Своё правило партнёра перебивает общее; экрана нет.

**Моё решение (на проверку владельцу):** строку «вся сеть» видит и пишет только
роль без ограничения по точкам, в правило «свой человек» (`0269`) она не входит —
иначе каждый офисный был бы виден каждому управляющему (как T130).
