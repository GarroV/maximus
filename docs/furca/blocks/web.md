# Блок: web

## Назначение

Каркас интерфейса: шаблоны, навигация, формы, локализация на три языка, админка
справочников. Выделен отдельно, чтобы экраны табеля, периода и отчётов строились на
готовом основании, а не каждый по-своему.

## API-контракт

Отдаёт другим блокам:

- базовый шаблон с навигацией, переключателем языка и индикатором тенанта и роли;
- набор компонентов оформления: таблица с итогами, форма, диалог подтверждения,
  плашка ошибки, метка регистра учёта;
- соглашение по htmx: частичные обновления возвращают фрагмент шаблона, а не JSON;
  атрибуты `hx-*` только в шаблонах, свой JavaScript — только в островке табеля;
- функции локализации: строки через штатный механизм переводов Django, файлы
  переводов в репозитории.

Соглашение по числам, обязательное для всех экранов: деньги выравниваются по правому
краю моноширинным начертанием, разделители — по локали, ноль отличается от пустого
значения визуально.

## Зависимости

Блоки: `auth` (текущий пользователь, права).

Внешнее: Django 6.1 (шаблоны, `django.contrib.admin`, механизм переводов),
htmx 2.x — версия зафиксирована, файл лежит в `static/`, не тянется с CDN.

Компоненты — в `templates/web/components/README.md` (канонический список, здесь не
дублируется).

Маршруты — в `docs/routes.md` (собирается из кода `manage.py routes --write` и
сверяется тестом); здесь не дублируются.

Каталоги переводов: `src/locale/en/LC_MESSAGES/` и `src/locale/sr_Latn/`.
Русского каталога нет и не нужно: русский — язык исходника, и без перевода
gettext отдаёт сам ключ. Записи в `.po` вносятся руками, рядом с соседними;
`makemessages` по рабочему каталогу не запускается (переписывает каталог целиком,
см. `CLAUDE.md`). Сборка `.mo` — `manage.py compilemessages`.

Переменные окружения, которые видит интерфейс: `DEV_LOGIN`, `SEED_USER_PASSWORD`,
`UI_LANGUAGE` (закрепляет язык страниц; пусто — язык выбирает человек).

## Статус

**2026-09-30 — T224 (issue #269, D081) сдаётся, ветка `feat/web-filters`.**

Где стою: отбор `/expenses/` и `/invoices/` — ссылками (`components/filters.html`,
`filter_links.py`), без `<select>` и «Показать». Месяц — соседние месяцы; точки,
регистры, оплата — ряды `.seg`; статья и контрагент — ряд «все / выбранное /
выбрать…» → страница выбора с поиском (`/expenses/filter/item/`,
`/invoices/filter/counterparty/`), в пустом результате «Сбросить поиск». Ряд из
одного варианта не рисуется. Разбор адреса — прежний `filters_from`, API не тронут.

Решения блока: длинные списки — отдельная страница выбора (подсказка в поле —
тот же выпадающий список и без скрипта не работает); даты «с — по» заменены
листанием месяцев, произвольный диапазон читается из адреса и показан выбранным;
ссылки повторяют присланный номер отбора как есть — чужой и выдуманный неотличимы.
