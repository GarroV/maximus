# Блок: facts

Состояние блока, а не хроника: история решений и проверок — в `git log`
(до 26.10.2026 этот файл вёл журнал на 1184 строки; он остался в истории).

## Назначение

Центральная таблица фактов — единственное место, куда стекаются первичные
финансовые события: выручка, сырьё, фактуры поставщиков, зарплата, наличные,
переводы, налоги. Модули пишут сюда, а не заводят своё хранилище. Вокруг неё
блок держит справочник статей, расходы из кассы с разнесением по точкам и —
с T198 — банковскую выписку, которая сводится с уже внесённым.

## API-контракт

**Таблицы фактов.** `facts` (строка = позиция документа), `source_documents`,
`fact_batches`; `expense_items` (статья ссылается на строку P&L);
`allocation_rules` с ровно одним ключом — контрагент или статья.
Запись — `upsert_fact` по `dedup_key` (повтор не создаёт строку), закрытый
месяц правится сторно и новой строкой (D020), без статьи — строка P&L
`unclassified`, она же инбокс (D076). Представления `pnl_lines`, `pnl_by_unit`,
`pnl_by_network`, `facts_unallocated` — все `security_invoker`.

**Выписка банка (T198, миграция 0276).**

| таблица | что | ключ от повтора |
|---|---|---|
| `bank_statements` | загруженный файл: формат, счёт, банк, период, итог разбора | `(tenant, content_hash)` — тот же файл второй раз отказ |
| `bank_lines` | операция: дата, направление `out`/`in`, сумма > 0, контрагент, назначение, ссылка банка; `duplicate_of`, `not_ours_*` с причиной | `(tenant, dedup_key)` среди оригиналов — дубль ссылается на первую |
| `bank_line_links` | чем закрыта строка: `fact_key` и как — `auto`, `manual`, `paid`, `inbox` | `(tenant, fact_key)` — один факт закрывает одну строку |

Доступ: изоляция партнёра + ограничительная политика «право
`suppliers.classify`» на все три таблицы; приложению выданы только нужные
действия (связь можно удалить, строку и выписку — нет).

Код: `src/bankstatement/` — чистый разбор (`reader`, `camt`, `formats.yaml`),
ключ строки (`keys`), правило сопоставления (`matching`); `src/web/bank.py` —
запись и решения; `src/web/bank_views.py` — экраны `/statement/`,
`/statement/upload/`, `/statement/lines/<id>/`.

Правило сопоставления: ровно один внесённый платёж той же суммы в окне
±5 дней → сведено; несколько — решает контрагент, иначе «нужно решить»; нет
платежа, но контрагент узнан и у него ровно один неоплаченный счёт с
остатком, равным сумме, → оплата счёта датой выписки. Остальное ждёт решения
человека: оплатить счёт, сопоставить с платежом, в инбокс, «не наш» с причиной.
Пока решения нет, строки в P&L нет. Оборот на экране дубли не считает.

## Исследование форматов (T198)

Нашли: единого формата НБС нет. Банки Сербии отдают свой XML (Banca Intesa
iBank — `stmtrs/stmttrn`, Raiffeisen — `Stavke` с атрибутами), Halcom-клиенты
умеют ISO 20022 camt.053, все — CSV/xlsx. Готового разборщика сербских izvod с
открытым кодом нет; `camt053` на PyPI — один автор и сырой, `mt-940` нужен
только для MT940, которого у сербских банков не видно.

Взяли: свой разбор camt.053 и XML-профилей на `xml.etree` с запретом
DTD/сущностей через обработчики expat; профили банков и синонимы заголовков
таблиц — данными в `formats.yaml`, без ветвления по стране. Ключ строки —
счёт + ссылка банка, без ссылки — составной из даты, суммы, сторон и
назначения с номером повтора.

Если владелец согласится — `defusedxml` как зависимость вместо своего запрета
DTD (сейчас не ставили).
